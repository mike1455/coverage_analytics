# Moscow Coverage Analytics

Локальное браузерное приложение для анализа покрытия обслуживанием по данным ЕДЦ и реестру МКД МЖИ. В нём есть дашборд, карта Москвы, тепловая карта заявок 2026 года, рейтинги 12 округов, таблица домов и подъездов с карточками, а также импорт ежемесячных выгрузок с проверкой качества.

Приложение запускается на одном компьютере по адресу `http://localhost:8000`. Ему не нужны VPS, СУБД, QGIS, Electron или публичный сайт. Все реестры и заявки обрабатываются в браузере (IndexedDB и Web Worker) и **не покидают компьютер**.

> **Главное правило.** «Покрытие» здесь означает **найденную настройку обслуживания подъездов в ЕДЦ** (`address_to_organization` и `entrances_to_address_binding`). Это не подтверждённое физическое подключение. «Нет найденной привязки» не значит «отключён». Если дом не сопоставлен, спорный или о нём мало данных, он показывается как «недостаточно данных», а не как «нет». Режим «Подтверждённое подключение» в интерфейсе пока выключен: для него нужен отдельный реестр.

## 1. Быстрый старт (Windows)

1. Установите **Python 3.9+** (при установке отметьте «Add Python to PATH»). Браузер: Chrome, Edge или Яндекс.Браузер свежей версии; Firefox 115+.
2. Скачайте репозиторий: кнопка **Code → Download ZIP** на GitHub или `git clone`.
3. В папке приложения откройте PowerShell и выполните:

   ```powershell
   py -3 serve.py
   ```

   Браузер откроется на `http://localhost:8000`. Если команда `py` не найдена, используйте `python serve.py`.
4. Нажмите **«Загрузить файлы»** и перетащите реестр МЖИ (`.xlsx`). На экране сразу появятся подлинные численности МКД по 12 округам.
5. Затем загрузите выгрузки ЕДЦ (см. раздел 2). После этого появятся сопоставление, рейтинги покрытия и заявки.

**Удобный вариант.** Положите файлы в папку `data/local/` (она исключена из git). Приложение найдёт их само и предложит импорт одной кнопкой.

Подойдёт и `python -m http.server 8000`, но тогда не будет работать офлайн-подложка PMTiles: стандартный сервер Python не поддерживает Range-запросы. `serve.py` их поддерживает, слушает только `127.0.0.1` и использует только стандартную библиотеку.

## 2. Какие файлы нужны

| Источник | Формат | Откуда | Обязателен |
|---|---|---|---|
| Реестр МКД МЖИ | `.xlsx` или `.csv`, колонки `Код, Округ, Район, Наименование/адрес, ФИАС, UNOM, Управляющая организация` | выгрузка МЖИ | да (основа рейтингов по округам) |
| ЕДЦ, **вариант A**: три исходных CSV | `01_дома.csv` (SQL № 2), `02_подъезды.csv` (SQL № 3), `03_заявки_2026.csv` (SQL № 4) | DBeaver | один из вариантов A/B |
| ЕДЦ, **вариант B**: два объединённых CSV | `Дома_ЕДЦ_2026_с_заявками.csv`, `Подъезды_ЕДЦ_2026_с_заявками.csv` | `tools/merge_edc_*.py` | один из вариантов A/B |
| ЕДЦ, **вариант C**: только заявки | `03_заявки_2026.csv` поверх уже загруженного снимка адресов | DBeaver | по желанию |
| Контрольные отчёты S2 | `*.control.txt` | `tools/merge_edc_*.py` | по желанию, показываются в разделе «Качество» |
| Геоданные | CSV `unom,lat,lon[,source,accuracy]` или GeoJSON с `properties.UNOM` | любые разрешённые источники | по желанию |

Шаблоны заголовков лежат в `data/templates/`. **Тип файла определяется по заголовкам, а не по имени**, поэтому файлы можно выбрать или перетащить все сразу. Заголовки, усечённые PostgreSQL до 63 байт (например, `Последняя версия записи адреса (is_l`), распознаются.

**Вариант A** выполняет в браузере тот же алгоритм объединения, что и скрипты из инструкции S2. Совпадение строка в строку проверяется тестом `tests/parity.test.mjs`. Так что запускать Python-скрипты не обязательно.

Требования к экспорту из DBeaver: весь результат без `LIMIT`, формат CSV, заголовки включены, UTF-8 (Windows-1251 тоже распознаётся), разделитель `,`, `;` или табуляция. **Не пересохраняйте файлы через Excel**: он портит UUID, УНОМ и ведущие нули.

SQL № 1, № 5 (контрольные) и № 6 (платные дефекты) для импорта не нужны: признаки жилого и актуального дома и платные дефекты уже есть в SQL № 2 и № 3.

## 3. Ежемесячное обновление

**«Обновить данные»** → выберите файлы → **«Проверить и показать изменения»** → посмотрите предпросмотр → **«Применить снимок»**.

Что показывает предпросмотр:

- критические ошибки, которые останавливают импорт: нет обязательных колонок, повтор ключа дома, дубликат агрегата заявок, сломанный CSV;
- предупреждения: строки без ФИАС, некорректный ФИАС, расхождение числа подъездов между файлами и т. п.;
- новые, изменённые и исчезнувшие адреса относительно прошлого снимка;
- несопоставленные агрегаты заявок по типам ключей (`UNKNOWN`, `entrances.id`, `NUMBER:`);
- KPI «сейчас → после»;
- дату среза (её можно поправить).

Правила обновления:

- **Снимок источника заменяется атомарно.** Накопительные заявки 2026 года **заменяются, а не складываются** с прошлым месяцем. Если отменить импорт или он прервётся, текущие данные не изменятся.
- **Ручная работа сохраняется:** геоточки, контуры зданий, зоны подъездов и ручные соответствия МЖИ↔ЕДЦ хранятся отдельно от выгрузок.
- **Исчезнувшие объекты не удаляются безвозвратно:** они помечаются как отсутствующие в последнем снимке (`not_in_latest_snapshot`), последняя известная запись сохраняется.
- Если адрес в МЖИ изменился, геометрия **не перемещается**: точка получает отметку «требует проверки».
- История снимков (даты, файлы, KPI) хранится в разделе «Импорт / качество». Помесячный ряд заявок не строится: разница двух накопительных выгрузок не равна потоку за месяц.

## 4. Как считаются показатели

**Сопоставление МЖИ ↔ ЕДЦ** (ТЗ §3.3):

1. Основной ключ — **УНОМ** (текст; ведущие нули не учитываются).
2. Если у одного УНОМ несколько записей ЕДЦ, правило выбора прозрачное: единственная запись → единственная актуальная (`actual = true`) → единственная актуальная «Жилое». Во всех остальных случаях это **конфликт**: дом не оценивается, а соответствие можно подтвердить вручную в карточке дома.
3. **ФИАС** — резервный ключ, только при однозначном совпадении. ФИАС должен быть корректным UUID и не повторяться в МЖИ, а запись ЕДЦ не должна быть уже занята по УНОМ другим домом. В реестре МЖИ от 19.10.2026 найдено 8 некорректных значений ФИАС (`nan`, `0x2a`, усечённое), 1 157 пустых и 55 повторяющихся.
4. Одна запись ЕДЦ не может представлять два дома МЖИ.
5. Текстовый адрес используется только для поиска и ручной проверки, но не как ключ.

**Оценённый дом** — дом из МЖИ, однозначно сопоставленный с записью ЕДЦ, у которой `actual = true`, `house_type = 'Жилое'` и подъездов больше нуля. Только такие дома входят в знаменатель долей.

| Статус | Условие | Цвет |
|---|---|---|
| Все подъезды с найденной привязкой | `подъездов с привязкой = подъездов всего > 0` | зелёный ✓ |
| Частичная привязка | `0 < с привязкой < всего` | оранжевый ◐ |
| Нет найденной привязки | `с привязкой = 0` | красный ⊗ (не «отключён») |
| Недостаточно данных | не найден в ЕДЦ, конфликт, актуальность неизвестна, тип не «Жилое», нет подъездов | серый ? |
| Неактуальный / нежилой | `actual = false` или `house_type = 'Нежилое'` | отдельный скрываемый слой |

- **% полностью покрытых** = полностью покрытые / оценённые дома.
- **% подъездов с привязкой** = подъезды с привязкой / подъезды оценённых домов (без строк-заглушек).
- **Заявки 2026** — сумма агрегатов **только уровня «Дом»** (SQL № 4). Уровни «Дом» и «Подъезд» никогда не складываются. Заявки с ключом `UNKNOWN`, по резервному `entrances.id` или по номеру подъезда по подъездам не распределяются. Поквартальная разбивка есть только для «всех заявок». IV квартал 2026 года частичный.
- **Рейтинг**: рядом с каждым местом видны числитель, знаменатель, полнота выборки и дата среза. Округа, где оценено меньше 30 домов, помечаются «малая выборка» и места не получают. Строки МЖИ без округа (4 шт.) в рейтинг не входят.
- Объём фонда МЖИ («МКД МЖИ») показывается отдельно и **не выдаётся за рейтинг подключения**.

## 5. Карта, подложка и геоданные

**Подложки.** Переключатель находится в правом верхнем углу карты. Варианты:

- офлайн OSM (PMTiles);
- CARTO (светлая или тёмная по теме интерфейса);
- OpenStreetMap;
- 2ГИС (онлайн; перед использованием проверьте условия 2ГИС);
- без подложки.

Скачать тайлы Яндекса или 2ГИС для офлайн-работы нельзя: их условия запрещают хранить тайлы вне собственных API. Массовое скачивание тайлов с серверов OpenStreetMap тоже запрещено. Легальный офлайн-вариант — **вырезка Москвы из сборки OpenStreetMap в формате PMTiles**:

```powershell
# 1) скачайте pmtiles.exe: https://github.com/protomaps/go-pmtiles/releases → положите в tools\bin\
# 2) вырежьте Москву (один файл ~100–400 МБ, данные © участники OpenStreetMap, ODbL):
py -3 tools/get_basemap.py
# 3) запускайте приложение через serve.py — подложка «Офлайн OSM» включится автоматически
py -3 serve.py
```

**На карте только дома с сохранённой геопозицией.** Случайных или «примерных» точек нет. Дома без координат доступны в таблице, поиске и рейтингах. Способы получить координаты:

- **«Геопривязка района (OSM)»** — до 50 домов одного района через OSM Nominatim. Работает только после вашего согласия и со скоростью 1 запрос в секунду. Отправляется только текст адреса (без УНОМ, ФИАС, ЕДЦ и заявок). Точка сохраняется, только если в OSM совпал номер дома, и получает статус «требует проверки». Массовое геокодирование всей базы через публичный Nominatim запрещено [его политикой](https://operations.osmfoundation.org/policies/nominatim/).
- **Карточка дома → «Найти координаты (OSM)»**: кандидаты показываются на карте, вы выбираете правильный.
- **«Указать на карте»** — точка ставится вручную; **«Нарисовать контур»** — полигон здания (Leaflet-Geoman).
- **Зоны подъездов**: в карточке у каждого подъезда есть кнопка «Зона». Это **условные** зоны (estimated) — по номерам подъездов реальные границы не восстановить. Зону можно отметить проверенной.
- **Импорт CSV/GeoJSON** с UNOM. Можно, например, подготовить координаты из адресного реестра data.mos.ru, где есть UNOM. Проверенные и ручные точки по умолчанию не перезаписываются.
- **Экспорт GeoJSON**: точки, контуры и зоны вместе с источником и точностью.

**Границы округов и районов** для заливки карты загружаются кнопкой из OSM (Overpass API, без отправки ваших данных) или из своего GeoJSON. Названия сопоставляются с округами и районами МЖИ. Схема 12 округов на дашборде работает без всяких границ.

**Тепловая карта заявок** (Leaflet.heat) строится только по геокодированным домам и всегда подписана, например: «по 30 геокодированным домам из N домов с заявками». Логарифмическая шкала меняет только цвет. Числа в карточках и подсказках остаются исходными.

## 6. Резервные копии и хранилище

- **«Геоданные и ручные правки»** — маленький JSON: точки, контуры, зоны подъездов, ручные соответствия, границы.
- **«Полная копия»** — все снимки, NDJSON со сжатием gzip.
- **«Восстановить»** — из любого из этих файлов.

Объём. Полная выгрузка ЕДЦ (около 300 тыс. адресов и 400 тыс. строк подъездов) занимает в браузере примерно 0,3–0,5 ГБ. Во время ежемесячного обновления новый снимок пишется рядом со старым, поэтому временно нужно вдвое больше места. Импорт идёт потоково в Web Worker. На синтетических данных вдвое больше реальных (300 тыс. адресов, 786 тыс. строк подъездов, 780 МБ CSV) он занимает около 2 минут. Если места не хватит, импорт остановится с сообщением, а текущие данные не изменятся. Режим инкогнито не подходит: там хранилище ограничено памятью и стирается при закрытии.

Данные IndexedDB привязаны к профилю браузера и адресу `http://localhost:8000`. Если открыть приложение на другом порту, браузере или компьютере, данные будут пустыми. Делайте копию после ручной георазметки и после каждой ежемесячной загрузки.

## 7. Python-инструменты (`tools/`)

| Скрипт | Назначение |
|---|---|
| `merge_edc_houses.py`, `merge_edc_entrances.py` | скрипты из инструкции S2 (без изменений): 3 CSV → 2 объединённых CSV + `.control.txt` |
| `prepare_mji.py` | реестр МЖИ XLSX → CSV (текстовые значения, сводка качества), без сторонних библиотек |
| `get_basemap.py` | офлайн-подложка Москвы `data/local/moscow.pmtiles` |
| `make_synthetic_data.py` | **синтетические** выгрузки для тестов и нагрузочной проверки (не для аналитики) |

```powershell
py -3 tools\merge_edc_houses.py --houses .\01_дома.csv --requests .\03_заявки_2026.csv --output .\Дома_ЕДЦ_2026_с_заявками.csv
py -3 tools\merge_edc_entrances.py --entrances .\02_подъезды.csv --requests .\03_заявки_2026.csv --output .\Подъезды_ЕДЦ_2026_с_заявками.csv
```

core/                      CSV-парсер, XLSX-читатель, заголовки, МЖИ, ЕДЦ (S2), округа
vendor/                    Leaflet 1.9.4, Leaflet.heat 0.2.0, Leaflet-Geoman free 2.20.2, protomaps-leaflet 5.1.0, fflate 0.8.2, osmtogeojson 3.0.0-beta.5

## 9. Тесты

```powershell
node --test "tests/*.test.mjs"                                 # ядро, аналитика, геомодуль, паритет с Python S2
py -3 -m unittest discover -s tests -p "test_*.py"             # Python-инструменты, Range в serve.py
node tests/e2e/run.mjs                                         # сквозной сценарий в Chromium (нужен Playwright)
```

Сквозной тест (`tests/e2e/run.mjs`) проверяет на синтетических данных:

- импорт МЖИ и трёх CSV ЕДЦ через интерфейс;
- совпадение KPI интерфейса с независимым расчётом в node;
- отсутствие двойного счёта заявок;
- повторный импорт идентичного снимка (0 изменений);
- сохранность геоданных после обновления;
- одинаковые KPI в режимах «3 сырых CSV» и «2 объединённых CSV»;
- обновление только заявок;
- полную резервную копию и восстановление.

## 10. Ограничения

1. Флага **подтверждённого подключения** в исходных данных нет. Все доли покрытия — прокси «по найденным привязкам ЕДЦ». У таблиц связей нет проверенного периода действия.
2. Реальные рейтинги покрытия появляются только после импорта **полных** CSV ЕДЦ. Без них интерфейс показывает честные пустые состояния, а не нули.
3. МЖИ (~35,9 тыс. МКД) и ЕДЦ (~295 тыс. адресов любых типов) — разные совокупности. Округ есть только у МЖИ, поэтому заявки по адресам ЕДЦ вне МЖИ в рейтинг округов не попадают; их сумма показана в отчёте о качестве.
4. Номер подъезда в SQL определяется эвристикой. Значение `[ID подъезда: UUID]` — не номер.
5. «Без даты закрытия» — прокси по `close_date` (`9999-12-31` значит «не закрыта»), а не статус процесса.
6. Тепловая карта показывает только геокодированную подвыборку.
7. Браузерное хранилище не вечное — нужны резервные копии.
