# Аналитика покрытия (Москва)

Локальное браузерное приложение: какие дома Москвы обслуживаются в ЕДЦ, где обслуживается только часть подъездов и где дом не обслуживается, а также сколько по домам заявок 2026 года. В нём есть сводная картинка по всей Москве (с выгрузкой в PNG), карта домов в цветах статуса, карта активности заявок по районам, сравнение 12 округов и районов с фильтрами, таблица домов с карточками, выгрузка всего в Excel и импорт ежемесячных выгрузок с проверкой качества.

Приложение запускается на одном компьютере по адресу `http://localhost:8000`. Ему не нужны VPS, СУБД, QGIS, Electron или публичный сайт. Все реестры и заявки обрабатываются в браузере (IndexedDB и Web Worker) и **не покидают компьютер**.

> **Как читать цвета.** **Зелёный**: дом обслуживается в ЕДЦ (найден в выгрузке, к обслуживанию привязаны все его подъезды). **Розовый**: обслуживается часть подъездов. **Красный**: дом не обслуживается в ЕДЦ (его нет в выгрузке ЕДЦ или ни один подъезд не привязан). **Серый**: данных не хватает (спорное сопоставление, нет сведений о подъездах и настройке) или адрес в ЕДЦ неактуальный или нежилой. «Обслуживается» определяется по настройкам обслуживания подъездов в ЕДЦ (`address_to_organization` и `entrances_to_address_binding`). Активность (заявки) показывается отдельными показателями, а не цветом статуса.

## 1. Быстрый старт (Windows)

**Самый короткий путь:**
1. Положите выгрузки в папку **`data/input`** внутри приложения (подробности в `data/input/README.md`).
2. Дважды щёлкните `start.bat`.
3. В открывшемся браузере нажмите **«Загрузить из папки выгрузок»**.

Если в `data/input` нужных файлов нет, приложение ищет их в запасной папке `%USERPROFILE%\Desktop\Выгрузка по адресам\ФАЙЛЫ ИТОГ`. Имена по умолчанию совпадают с теми, под которыми файлы сохранил DBeaver (длинные тире в именах оставлены, потому что это настоящие имена файлов):

| Роль | Имя файла по умолчанию |
|---|---|
| Реестр МЖИ | `19.10.26_МКД_SELECT_t_content_code_AS_Код_t_content_District_AS_Округ_t_cont_202610191348.xlsx` |
| SQL № 2, дома | `Запрос № 2. Выгрузка № 1 — ВСЕ адреса, одна строка на дом.csv` |
| SQL № 3, подъезды | `Запрос № 3. Выгрузка № 2 — ВСЕ адреса и подъезды, одна строка на подъезд.csv` |
| SQL № 4, заявки | `Запрос № 4. Выгрузка № 3 — заявки 2026 по дому И по подъезду в ОДНОМ файле.csv` |

Кнопка «Открыть папку» в этом окне открывает папку в проводнике. Папку и любое имя можно изменить прямо в окне «Папка с выгрузками»: впишите своё или выберите из подсказки со списком файлов папки. Вместо имени можно указать полный путь. Рядом с каждым файлом видно, найден ли он, его размер и дату. Файлы, уже загруженные в приложение, отмечены и по умолчанию не выбраны. Настройки сохраняются в `config/sources.local.json` (в git не попадает) и подставляются при следующем запуске. Запросы № 1 и № 5 (контрольные), № 6 (платные дефекты) и `.md` для расчётов **не нужны**. Если перетащить их в мастер импорта, они будут пропущены с пояснением.

Браузер сам не может читать файлы с диска по пути, поэтому их отдаёт `serve.py`: только файлы из этих настроек, только с допустимыми расширениями (`.csv`, `.xlsx`, `.geojson`, `.json`, `.txt`) и только на `localhost`.

Подробно:

1. Установите **Python 3.9+** (при установке отметьте «Add Python to PATH»). Браузер: Chrome, Edge или Яндекс.Браузер свежей версии; Firefox 115+.
2. Скачайте репозиторий: кнопка **Code**, затем **Download ZIP** на GitHub или `git clone`.
3. В папке приложения откройте PowerShell и выполните:

   ```powershell
   py -3 serve.py
   ```

   (или дважды щёлкните `start.bat`). Браузер откроется на `http://localhost:8000`. Если команда `py` не найдена, используйте `python serve.py`.
4. Нажмите **«Загрузить из папки выгрузок»** или **«Выбрать файлы вручную»** и укажите реестр МЖИ (`.xlsx`). Сразу появится число МКД по 12 округам.
5. Затем загрузите выгрузки ЕДЦ (см. раздел 2). После этого появятся сводка, статусы домов, сравнение округов и районов и заявки.
6. Один раз скачайте офлайн-карту: кнопка **«Скачать карту Москвы»** на карте (подробнее в разделе 5).

Все загруженные данные остаются в браузере между запусками, повторно их загружать не нужно. Обновлять стоит только ежемесячные выгрузки.

`serve.py` слушает только `127.0.0.1` и использует только стандартную библиотеку Python. Обычный `python -m http.server 8000` тоже откроет приложение, но без загрузки из папки и без офлайн-карты.

## 2. Какие файлы нужны

| Источник | Формат | Откуда | Обязателен |
|---|---|---|---|
| Реестр МКД МЖИ | `.xlsx` или `.csv`, колонки `Код, Округ, Район, Наименование/адрес, ФИАС, UNOM, Управляющая организация` | выгрузка МЖИ | да (основа всех расчётов по округам и районам) |
| ЕДЦ, **вариант A**: три исходных CSV | `01_дома.csv` (SQL № 2), `02_подъезды.csv` (SQL № 3), `03_заявки_2026.csv` (SQL № 4) | DBeaver | один из вариантов A/B |
| ЕДЦ, **вариант B**: два объединённых CSV | `Дома_ЕДЦ_2026_с_заявками.csv`, `Подъезды_ЕДЦ_2026_с_заявками.csv` | `tools/merge_edc_*.py` | один из вариантов A/B |
| ЕДЦ, **вариант C**: только заявки | `03_заявки_2026.csv` поверх уже загруженного снимка адресов | DBeaver | по желанию |
| Контрольные отчёты S2 | `*.control.txt` | `tools/merge_edc_*.py` | по желанию, показываются в разделе «Качество» |
| Геоданные | CSV `unom,lat,lon[,source,accuracy]` или GeoJSON с `properties.UNOM` | любые разрешённые источники | по желанию |

Шаблоны заголовков лежат в `data/templates/`. **Тип файла определяется по заголовкам, а не по имени**, поэтому файлы можно выбрать или перетащить все сразу. Заголовки, усечённые PostgreSQL до 63 байт (например, `Последняя версия записи адреса (is_l`), распознаются.

**Вариант A** выполняет в браузере тот же алгоритм объединения, что и скрипты из инструкции S2. Совпадение строка в строку проверяется тестом `tests/parity.test.mjs`. Так что запускать Python-скрипты не обязательно.

Требования к экспорту из DBeaver: весь результат без `LIMIT`, формат CSV, заголовки включены, UTF-8 (Windows-1251 тоже распознаётся), разделитель `,`, `;` или табуляция. **Не пересохраняйте файлы через Excel**: он портит UUID, УНОМ и ведущие нули.

SQL № 1, № 5 (контрольные) и № 6 (платные дефекты) для импорта не нужны: признаки жилого и актуального дома и платные дефекты уже есть в SQL № 2 и № 3.

## 3. Ежемесячное обновление

1. Нажмите **«Обновить данные»** и выберите файлы (или **«Загрузить из папки выгрузок»**).
2. Нажмите **«Проверить и показать изменения»** и посмотрите предпросмотр.
3. Нажмите **«Применить снимок»**.

Что показывает предпросмотр:

- критические ошибки, которые останавливают импорт: нет обязательных колонок, повтор ключа дома, строка заявок, повторённая в файле целиком, сломанный CSV;
- агрегаты заявок одного подъезда или адреса, записанные по-разному («1А» и «1а», лишние пробелы, регистр UUID) или разбитые запросом на несколько строк (например, по разным УНОМ), объединяются, заявки складываются; это показывается предупреждением с примерами. Исходные скрипты S2 на таких данных останавливаются;
- предупреждения: строки без ФИАС, некорректный ФИАС, расхождение числа подъездов между файлами и т. п.;
- новые, изменённые и исчезнувшие адреса относительно прошлого снимка;
- несопоставленные агрегаты заявок по типам ключей (`UNKNOWN`, `entrances.id`, `NUMBER:`);
- показатели до и после обновления;
- дату среза (её можно поправить).

Правила обновления:

- **Снимок источника заменяется атомарно.** Накопительные заявки 2026 года **заменяются, а не складываются** с прошлым месяцем. Если отменить импорт или он прервётся, текущие данные не изменятся.
- **Ручная работа сохраняется:** геоточки, контуры зданий, зоны подъездов и ручные соответствия МЖИ и ЕДЦ хранятся отдельно от выгрузок.
- **Исчезнувшие объекты не удаляются безвозвратно:** они помечаются как отсутствующие в последнем снимке (`not_in_latest_snapshot`), последняя известная запись сохраняется.
- Если адрес в МЖИ изменился, геометрия **не перемещается**: точка получает отметку «требует проверки».
- История снимков (даты, файлы, KPI) хранится в разделе «Импорт и качество данных». Помесячный ряд заявок не строится: разница двух накопительных выгрузок не равна потоку за месяц.

## 4. Как считаются показатели

**Сопоставление МЖИ и ЕДЦ** (ТЗ §3.3):

1. Основной ключ: **УНОМ** (текст, ведущие нули не учитываются).
2. Если у одного УНОМ несколько записей ЕДЦ, выбирается по порядку: единственная запись, затем единственная актуальная (`actual = true`), затем единственная актуальная с типом «Жилое». Во всех остальных случаях это **конфликт**: дом не оценивается, а соответствие можно подтвердить вручную в карточке дома.
3. **ФИАС** используется как резервный ключ и только при однозначном совпадении. ФИАС должен быть корректным UUID и не повторяться в МЖИ, а запись ЕДЦ не должна быть уже занята по УНОМ другим домом. В реестре МЖИ от 19.10.2026 найдено 8 некорректных значений ФИАС (`nan`, `0x2a`, усечённое), 1 157 пустых и 55 повторяющихся.
4. Одна запись ЕДЦ не может представлять два дома МЖИ.
5. Текстовый адрес используется только для поиска и ручной проверки, но не как ключ.

**Статус дома** (цвет на карте, в сводке, в таблицах и в Excel):

| Статус | Условие | Цвет |
|---|---|---|
| Обслуживается в ЕДЦ | дом сопоставлен с ЕДЦ и `подъездов с привязкой = подъездов всего > 0`; если подъезды в ЕДЦ не указаны, но у дома есть настройка обслуживания, дом тоже считается обслуживаемым | зелёный |
| Обслуживается часть подъездов | `0 < подъездов с привязкой < подъездов всего` | розовый |
| Не обслуживается в ЕДЦ | дома нет в выгрузке ЕДЦ (по УНОМ и ФИАС) или `подъездов с привязкой = 0` | красный |
| Нет данных | выгрузки ЕДЦ не загружены, спорное сопоставление (несколько записей ЕДЦ), нет сведений о подъездах и о настройке обслуживания | серый |
| Неактуальный или нежилой | `actual = false` или `house_type = 'Нежилое'` | светло-серый, отдельный скрываемый слой |

Показатели (одинаково считаются для Москвы, округа, района и ячейки сетки на карте):

- **Доля обслуживаемых домов** = (зелёные + розовые) / все дома реестра МЖИ.
- **Не обслуживается** = число красных домов; отдельно видно, сколько из них вовсе нет в выгрузке ЕДЦ.
- **Доля обслуживаемых подъездов** = подъезды с привязкой / подъезды домов, найденных в ЕДЦ (без строк-заглушек).
- **Заявки 2026**: сумма агрегатов **только уровня «Дом»** (SQL № 4). Уровни «Дом» и «Подъезд» никогда не складываются. Заявки с ключом `UNKNOWN`, по резервному `entrances.id` или по номеру подъезда по подъездам не распределяются. Поквартальная разбивка есть только для «всех заявок». IV квартал 2026 года частичный.
- **Заявок на дом** = заявки обслуживаемых домов / число обслуживаемых домов (за год или за выбранный квартал). Так можно сравнивать округа и районы разного размера.
- **Доля домов с заявками** = обслуживаемые дома, по которым в 2026 году была хотя бы одна заявка / все обслуживаемые дома.
- Без округа (4 строки МЖИ) дома входят в итоги по Москве, но мест в сравнении округов не получают. Если в знаменателе доли меньше 30 домов, значение помечается как неустойчивое: место не присваивается, на сводке район обведён пунктиром.

**Сводка** (первый раздел) собирает всё на одну картинку: итоги по Москве, 12 округов (цвет по выбранному показателю), состав домов по статусам в каждом округе, мозаику всех районов (каждый квадрат один район, справа в строке округа район с наименьшей долей обслуживаемых домов или с наибольшей активностью), заявки на дом по кварталам и списки районов-отстающих и самых активных. Кнопка **«Скачать картинку (PNG)»** сохраняет её для отчёта, **«Выгрузить всё в Excel»** сохраняет книгу с листами «Сводка», «Округа», «Районы» и «Дома» (у каждого дома статус, сопоставление, подъезды, заявки по кварталам и координаты с источником). В разделе «Округа и районы» выгружается выбранный округ, в таблице домов кнопка «Excel по фильтру» выгружает только отфильтрованные дома.

- **Таблицы округов и районов** сортируются кликом по заголовку и фильтруются полями под заголовками: в названии ищутся слова («зао»), в числовых столбцах вводится условие `>90`, `<50`, `>=10`, `10-20` или число; проценты вводятся в процентах. Непонятное условие подсвечивается красным и строки не отбрасывает. «Сбросить фильтры» возвращает полную таблицу.

## 5. Карта, подложка и геоданные

**Офлайн-карта Москвы скачивается один раз.** На карте в панели «Подложка» нажмите **«Скачать карту Москвы»** (та же кнопка есть в разделе «Импорт и качество данных»). Приложение через `serve.py` скачает вырезку Москвы из свежей сборки OpenStreetMap и сохранит её в файл `data/local/moscow.pmtiles` рядом с приложением. Объём несколько сотен мегабайт, загрузка занимает от 5 до 20 минут, ход загрузки виден в приложении. После этого карта открывается без интернета и включается сама.

- **Обновить карту** можно в любой момент кнопкой «Обновить карту» в разделе «Импорт и качество данных». Прежняя карта работает, пока идёт загрузка, и заменяется только после успешного окончания. Отмена или обрыв связи её не портят.
- Дата данных и размер карты видны в левом меню («Офлайн-карта») и в разделе импорта.
- Нужен разовый доступ к `build.protomaps.com` (через системный прокси Windows, если он настроен). Внешние программы не нужны, всё делает Python из стандартной библиотеки.
- То же из командной строки: `py -3 tools/get_basemap.py` (параметры: `--maxzoom 14` для файла поменьше, `--build ГГГГММДД` для конкретной сборки).

Почему именно так: условия Яндекс.Карт и 2ГИС запрещают сохранять их тайлы вне собственных API, массовое скачивание тайлов с серверов OpenStreetMap тоже запрещено. Сборки Protomaps из данных OpenStreetMap (лицензия ODbL) публикуются как раз для такой вырезки и хранения у себя.

**Другие подложки** (переключатель в правом верхнем углу карты, нужен интернет): CARTO (светлая или тёмная по теме интерфейса), OpenStreetMap, 2ГИС (перед использованием проверьте условия 2ГИС), без подложки.

**На карте домов точки окрашены по статусу** (зелёный, розовый, красный, серый), а округа или районы можно залить по любому показателю. На карте только дома с сохранённой геопозицией, случайных или «примерных» точек нет. Дома без координат есть в сводке, таблицах и поиске. Карта с подложкой видна сразу, даже до загрузки данных.

**Координаты всех домов.** Кнопка **«Найти координаты всех домов»** есть на карте и в разделе «Импорт и качество данных». В окне выбираются источники (галочками, выбор запоминается); они выполняются по порядку, и каждый ищет только дома, которые ещё без координат. Ход виден в цифрах: сколько записей или адресов получено, сколько домов проверено и найдено, процент.

1. **Адресный реестр Москвы (data.mos.ru), точно по UNOM.** Официальный «Адресный реестр объектов недвижимости города Москвы» (набор 60562): у каждого здания есть UNOM, центр и контур, поэтому адрес не разбирается вовсе, а контуры зданий сразу появляются на карте. Нужен бесплатный ключ API портала открытых данных (личный кабинет на data.mos.ru); он вводится прямо в окне и хранится только на этом компьютере в `config/geocoder.local.json`. Реестр читается один раз целиком (около 440 тысяч записей, 10-20 минут) и сохраняется в `data/local/mos_registry.json`. Без ключа можно скачать выгрузку набора с data.mos.ru в JSON и загрузить её кнопкой «Импорт CSV/GeoJSON»: формат с полями `UNOM`, `geoData`, `geodata_center` распознаётся.
2. **OpenStreetMap, по адресу, без ключа.** Если справочника ещё нет, `serve.py` скачивает адреса зданий Москвы через Overpass API (один раз) в `data/local/osm/moscow_addresses.json`. Москва делится на 64 небольших квадрата; каждый полученный квадрат сразу сохраняется в `data/local/osm/parts`, его дома тут же ищутся, сохраняются и появляются на карте, не дожидаясь конца загрузки. В окне видно, сколько адресов и частей получено и сколько домов уже на карте; окно можно свернуть, ход останется в углу экрана. Если сервер не успевает ответить за 90 секунд, квадрат делится на четыре меньших, а не ждёт; при сбое запрос повторяется на зеркалах (overpass-api.de, maps.mail.ru, overpass.kumi.systems). Части, которые не загрузились, и части, полученные до обрыва или закрытия приложения, не теряются: следующий запуск докачивает только недостающие. Сопоставление идёт в браузере: улица без учёта порядка слов и сокращений («Бочвара Академика ул.» = «улица Академика Бочвара»), номер дома с корпусом и строением точно, уточнение в скобках («Чехова ул. (Щербинка г.)») выбирает населённый пункт; если подходят здания в разных местах, дом не привязывается.
3. **Яндекс Геокодер, по адресу.** Нужен ключ API ([кабинет разработчика Яндекса](https://developer.tech.yandex.ru/), сервис «JavaScript API и HTTP Геокодер»), он вводится в окне и хранится только на этом компьютере. В Яндекс отправляются только адреса домов, которые остались без координат. Принимаются только ответы с видом «дом» в границах Москвы; если совпал номер дома без корпуса, точка помечается «требует проверки». Ответы сохраняются в `data/local/yandex_geocoder_cache.json`, повторный поиск лимит не тратит. Суточный лимит по умолчанию 1000 запросов (бесплатный тариф). Условия хранения результатов проверьте для своего тарифа.

Если источник недоступен, следующие всё равно выполняются. Скачанные адреса OSM и реестр Москвы обновляются ссылками внизу окна.

Найденные точки сохраняются в браузере (статусы «Реестр Москвы (UNOM)», «OSM по адресу» и «Яндекс Геокодер») и копией в файл `data/local/geocoded_houses.csv`: если данные браузера очистятся, его можно снова импортировать. Точки, указанные вручную, проверенные или загруженные из файла, не меняются. Дома без координат скачиваются списком в CSV.

**Координаты для файла отдельным скриптом.** Если удобнее без приложения, дважды щёлкните `geocode.bat` в папке приложения (или `py -3 tools/geocode_file.py`). Скрипт спросит путь к файлу XLSX или CSV (файл можно перетащить в окно), сам найдёт колонки с адресом и UNOM, предложит источники (реестр Москвы по UNOM, OpenStreetMap, Яндекс Геокодер, а также Nominatim по одному адресу в секунду) и ключи, покажет ход в цифрах. Исходный файл не меняется, рядом появляются:

- `<имя>_с_координатами.xlsx` (или `.csv`): все исходные колонки и новые «Широта», «Долгота», «Источник координат», «Точность»;
- `<имя>_без_координат.csv`: строки, для которых координаты не найдены;
- `<имя>_для_приложения.csv`: UNOM и координаты для загрузки в приложение кнопкой «Импорт CSV/GeoJSON».

Без вопросов: `py -3 tools/geocode_file.py "C:\путь\реестр.xlsx" --sources osm,yandex --yandex-key КЛЮЧ --yes`. Скачанные адреса OSM, реестр и ответы Яндекса общие с приложением (`data/local`), повторно не скачиваются.

Другие способы:

- **«Район через Nominatim»**: до 50 домов одного района через OSM Nominatim. Работает только после вашего согласия и со скоростью 1 запрос в секунду. Отправляется только текст адреса (без УНОМ, ФИАС, ЕДЦ и заявок). Точка сохраняется, только если в OSM совпал номер дома, и получает статус «требует проверки». Массовое геокодирование всей базы через публичный Nominatim запрещено [его политикой](https://operations.osmfoundation.org/policies/nominatim/).
- **«Найти координаты (OSM)»** в карточке дома: кандидаты показываются на карте, вы выбираете правильный.
- **«Указать на карте»** ставит точку вручную, **«Нарисовать контур»** рисует полигон здания (Leaflet-Geoman).
- **Зоны подъездов**: в карточке у каждого подъезда есть кнопка «Зона». Это **условные** зоны (estimated): по номерам подъездов реальные границы не восстановить. Зону можно отметить проверенной.
- **Импорт CSV/GeoJSON** с UNOM. Можно, например, подготовить координаты из адресного реестра data.mos.ru, где есть UNOM. Проверенные и ручные точки по умолчанию не перезаписываются.
- **Экспорт GeoJSON**: точки, контуры и зоны вместе с источником и точностью.

**Границы округов и районов** для заливки карты загружаются одной кнопкой **«Загрузить границы округов и районов»** (раздел «Импорт и качество данных» или панель справа от карты). `serve.py` берёт их из OpenStreetMap так, чтобы пережить перегрузку публичных серверов:

Ход загрузки виден в окне отдельно для округов и для районов: сколько границ в списке, сколько полигонов уже получено и откуда.

1. Overpass API (несколько серверов, с повторами) отдаёт только список границ: номер, название, уровень. Это лёгкий запрос.
2. Nominatim отдаёт полигоны этих границ пачками по 40, уже упрощёнными (несколько запросов).
3. Если Nominatim недоступен, полигоны берутся из Overpass и собираются из линий на месте.
4. Если недоступен Overpass, границы ищутся в Nominatim по названиям 12 округов и районов реестра.

Границы сохраняются в `data/local/osm/boundaries_okrug.geojson` и `boundaries_area.geojson` и в браузере; если данные браузера очистятся, приложение подхватит их из этих файлов без интернета. Названия сопоставляются с округами и районами МЖИ, в том числе с разными окончаниями («поселение Филимонковское» и «Филимонковский»); несопоставленные полигоны рисуются пунктиром. Можно загрузить и свой GeoJSON. Сводка и схема 12 округов работают без всяких границ.

**Активность заявок** показывается без «тепловой кляксы». Основной режим: **заливка районов** по выбранному показателю (заявок на дом, всего заявок, доля домов с заявками, открытых или критических на дом). Она считается по всем домам района и не зависит от того, у скольких домов есть координаты. Цвета идут классами по квантилям (в каждом классе примерно поровну районов), границы классов подписаны в легенде. Второй режим, **«Сетка 600 м»**, раскладывает дома с координатами по шестиугольникам и считает в каждом те же показатели; в легенде видно, по скольким домам построена сетка. Справа списки районов и домов с наибольшими значениями.

## 6. Резервные копии и хранилище

- **«Геоданные и ручные правки»**: небольшой JSON: точки, контуры, зоны подъездов, ручные соответствия, границы.
- **«Полная копия»**: все снимки, NDJSON со сжатием gzip.
- **«Восстановить»**: из любого из этих файлов.

Объём. Полная выгрузка ЕДЦ (около 300 тыс. адресов и 400 тыс. строк подъездов) занимает в браузере примерно 0,3-0,5 ГБ. Во время ежемесячного обновления новый снимок пишется рядом со старым, поэтому временно нужно вдвое больше места. Импорт идёт потоково в Web Worker. На синтетических данных вдвое больше реальных (300 тыс. адресов, 786 тыс. строк подъездов, 780 МБ CSV) он занимает около 2 минут. Если места не хватит, импорт остановится с сообщением, а текущие данные не изменятся. Режим инкогнито не подходит: там хранилище ограничено памятью и стирается при закрытии.

Данные IndexedDB привязаны к профилю браузера и адресу `http://localhost:8000` и сохраняются между запусками. Офлайн-карта хранится отдельно, в файле `data/local/moscow.pmtiles`. Если открыть приложение на другом порту, браузере или компьютере, данные будут пустыми. Делайте копию после ручной георазметки и после каждой ежемесячной загрузки.

- полную резервную копию и восстановление.

## 10. Ограничения

1. «Обслуживается» определяется по найденным в ЕДЦ настройкам обслуживания подъездов. Отдельного флага физического подключения в исходных данных нет, у таблиц связей нет проверенного периода действия.
2. Статусы и доли появляются только после импорта **полных** CSV ЕДЦ. Без них они остаются пустыми, а не нулевыми. Если SQL № 3 выгружает только подъезды с привязкой, доля обслуживаемых подъездов будет близка к 100%: тогда различия между округами видны по красным домам (нет в ЕДЦ) и по активности заявок.
3. МЖИ (около 35,9 тыс. МКД) и ЕДЦ (около 295 тыс. адресов любых типов) охватывают разные совокупности. Округ есть только у МЖИ, поэтому заявки по адресам ЕДЦ вне МЖИ в показатели округов не попадают; их сумма показана в отчёте о качестве.
4. Номер подъезда в SQL определяется эвристикой. Значение `[ID подъезда: UUID]` не является номером.
5. «Без даты закрытия» считается по `close_date` (`9999-12-31` значит «не закрыта»), а не статус процесса.
6. Сетка активности и точки на карте показывают только дома с координатами; заливка районов и сводка считаются по всем домам. Координаты по адресам OSM зависят от полноты адресов в OpenStreetMap: дома, которых там нет или чей адрес записан иначе, остаются без точки и выгружаются списком.
7. Браузерное хранилище можно случайно очистить (например, очисткой данных сайтов), поэтому делайте резервные копии.
